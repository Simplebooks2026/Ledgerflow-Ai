1. Project Mission

LedgerFlow AI is an intelligent, full-stack accounting platform that automates bookkeeping, transaction categorization, and financial reporting with AI-driven insights to keep business finances accurate and audit-ready.

The system implements strict double-entry accounting (debits = credits as a non-negotiable constraint), decimal-safe monetary arithmetic to prevent floating-point errors, an immutable audit log, multi-language support (English / Arabic with RTL), and AI-powered transaction categorization, receipt extraction, and a natural-language accounting assistant.

2. Architecture Overview

Frontend

React 18 + Vite + Tailwind CSS + shadcn/ui. Single-page application with client-side routing (react-router-dom). All financial calculations happen client-side using decimal-safe helpers (src/lib/money.js) and the accounting engine (src/lib/accounting.js).

Backend

Base44 platform (backend-as-a-service): persistent JSON entities with foreign-key relationships, serverless backend functions (Deno/TypeScript) for AI integration, built-in authentication, and Core integrations (InvokeLLM, file upload, email).

AI Layer

Five backend functions handle AI: aiCategorize (transaction categorization), aiAssistant (natural-language Q&A), aiInsights (rule-based insights), extractReceipt (vision OCR), seedDemoData (demo data generation). All use base44.asServiceRole.integrations.Core.InvokeLLM.

Data Integrity

Double-entry validation enforced on every journal entry before posting. Trial balance computed from posted entries. Reports (P&L, Balance Sheet, Cash Flow) calculated directly from the ledger — never stored as snapshots.

3. AI Prompts & Backend Functions

These are the exact prompts and logic used in each backend function. Each function runs server-side on Deno and is invoked from the frontend via the Base44 SDK.

1

aiCategorize

AI transaction categorization — suggests the best matching expense/revenue account for uncategorized bank transactions.

Prompt / Logic
You are an expert bookkeeping AI. For each bank transaction, suggest the best matching expense/revenue account.
Return JSON array. Each item: { id, account_id, confidence (0-100), transaction_type, tax_treatment }.
Transactions: <JSON of uncategorized transactions>
Available accounts: <JSON of chart of accounts>
Pick the account_id from the available accounts. Use expense accounts for money out (negative amount), revenue accounts for money in (positive amount).
Flow

1. Apply deterministic accounting rules first (confidence 100). 2. For unmatched transactions, call InvokeLLM with the prompt above and a JSON schema. 3. Merge rule + AI suggestions. 4. User reviews and accepts before posting.

2

aiAssistant

AI accounting assistant — answers natural-language questions using the user's authorized ledger data.

Prompt / Logic
You are an AI accounting assistant for a double-entry accounting platform. Answer the user's question using ONLY the provided financial summary. Do not invent figures. If the data is insufficient, say so. Distinguish actual data from calculations. Keep answers concise and cite the relevant accounts/date range when presenting numbers.

Financial summary (JSON):
<compact summary: totals, AR, AP, overdue invoices, unpaid bills, expense by account, counts>

User question: <the user's question>
Flow

1. Gather accounts, journal entries, invoices, bills, customers, vendors scoped to company_id. 2. Build a compact financial summary (revenue, expenses, net profit, AR, AP, overdue, expense breakdown). 3. Send summary + question to InvokeLLM. 4. Return answer + summary.

3

aiInsights

Rule-based financial insight engine — detects duplicates, large transactions, uncategorized items, overdue invoices/bills, and unreconciled transactions.

Prompt / Logic
(No LLM call — pure deterministic rules over posted journal entries, invoices, bills, and bank transactions.)
Flow

Checks: duplicate-looking entries (same date+description+amount), large transactions (>10,000), uncategorized bank transactions, overdue invoices, overdue bills, unreconciled bank transactions. Returns array of {type, severity, message}.

4

extractReceipt

AI vision receipt extraction — reads vendor, date, amounts from an uploaded receipt image/PDF.

Prompt / Logic
Extract the following fields from this receipt or invoice image. Return JSON. If a field is not present, use null.
Fields: vendor, date (YYYY-MM-DD), receipt_number, subtotal (number), tax (number), total (number), currency (ISO code).
Flow

1. Client uploads receipt via UploadPrivateFile (stored privately). 2. Pass file_url to this function. 3. InvokeLLM with vision (file_urls) + JSON schema. 4. Return extracted data to pre-fill the expense form.

5

seedDemoData

Seeds a demo company with 12 months of realistic double-entry accounting data for testing.

Prompt / Logic
(No LLM call — deterministic data generation.)
Flow

Creates: Acme Trading Co. (Demo), 25-account chart of accounts, VAT 5% tax code, 3 customers, 4 vendors, opening balances, 1 bank account, 12 months of invoices (with AR journal entries), payments, monthly expenses (with journal entries), vendor bills (with AP journal entries), and bank transactions. ~156 journal entries total.

7. How to Run — Open-Source Guide

Prerequisites: Node.js 18+, npm, and a Base44 account (free tier works). The app uses the Base44 SDK for backend services — entities, auth, and AI integrations run on the Base44 platform.
Option A — Run locally with Base44 backend (recommended)
1
Clone the repo and install dependencies: npm install
2
Install Base44 CLI: npm install -g base44@latest
3
Install Deno (local backend runtime)
4
Link the app: base44 link (one-time per clone; app id is in the Builder URL)
5
Login: base44 login (one-time per machine)
6
Start dev server: base44 dev — opens at http://localhost:5173
7
The app must be published at least once for the UI to load under base44 dev (frontend fetches app settings from the hosted app).
Option B — Frontend only against hosted backend
Run base44 dev --remote — serves the frontend locally but writes go to your app's production data.
Option C — Open in an HTML/code editor
Open the project folder in VS Code, Sublime Text, or any editor. The source is standard React/JS in src/, entity schemas in base44/entities/, and backend functions in base44/functions/. Use npm run build to produce a static bundle in dist/.
Seed demo data
After first login, go to Settings → Demo Data and click "Seed Demo Data" to populate a demo company with 12 months of realistic accounting entries (25 accounts, ~156 journal entries, invoices, bills, expenses, bank transactions).

8. Key Design Decisions

Double-Entry Integrity

Every journal entry is validated: total debits must equal total credits, each line needs an account, no negative amounts, no line with both debit and credit. Entries are draft until posted.

Decimal-Safe Money

All monetary arithmetic rounds to 2 decimals after every operation (Math.round((n + Number.EPSILON) * 100) / 100) to prevent floating-point drift.

Immutable Audit Log

Every financial action (create, post, update, delete, reconcile, import) is logged with user, action, module, record id, and details.

AI with Human Approval

AI categorization suggestions are never auto-posted. The user reviews and accepts/rejects each suggestion before a journal entry is created.

Multi-Language / RTL

All UI text uses translation keys. Arabic switches the entire layout to RTL (dir="rtl") including sidebar, tables, and forms.

Private Receipt Storage

Uploaded receipts use UploadPrivateFile — no public URL, access follows app permissions. Signed URLs are generated on demand for viewing.

Reports from Ledger

P&L, Balance Sheet, Cash Flow, and Trial Balance are all computed live from posted journal entry lines — never stored as snapshots, ensuring they always match the ledger.
